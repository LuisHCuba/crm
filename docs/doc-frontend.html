Decisões definidas

Estilização

— definido

Requisito

Visual único e próprio, não genérico. Tailwind já é usado no dia a dia, então o design system deve ir além do "shadcn padrão" — identidade visual customizada, não template.

Abordagem

  • Tailwind CSS como base utilitária (já tem experiência)
  • Componentes próprios construídos sobre primitivos acessíveis (Radix UI para comportamento: dialog, dropdown, tooltip, etc.)
  • Design tokens customizados (cores, espaçamentos, tipografia) para identidade visual única
  • Sem depender de lib visual pronta (sem Ant Design, sem MUI, sem Mantine como "skin")

Sidebar

— definido

Comportamento

  • Colapsável: o usuário pode expandir (mostra ícone + texto) ou minimizar (só ícone)
  • Quando minimizada, ao passar o mouse sobre um ícone de grupo (ex.: CRM), exibe um popover/flyout com as opções daquele grupo — permite navegar sem expandir o menu
  • O estado (expandido/colapsado) é salvo por usuário (persiste entre sessões)

Tema

— definido
  • Dark mode e light mode com toggle
  • Respeitar preferência do sistema operacional como padrão inicial
  • Persistir escolha do usuário

Referências visuais

— definido
ReferênciaO que pegar
NotionSidebar limpa e colapsável, flexibilidade de views, sensação de "workspace" organizado
HubSpot CRMFicha de registro com abas, timeline de atividades, kanban de negócios
OMIETabelas com filtros dinâmicos (colunas filtráveis, combinação de filtros em tempo real, salvar filtros)

Tabelas estilo OMIE — o que implementar

  • Filtro por coluna: clicar no header da coluna abre opções de filtro (contém, igual, maior que, entre datas…)
  • Múltiplos filtros ativos ao mesmo tempo, combinados (ex.: Status = Pendente AND Empresa = Padaria)
  • Filtros aparecem como chips/pills acima da tabela, removíveis individualmente
  • Salvar filtros como "visões" reutilizáveis (ex.: "Atrasados da semana", "Meus negócios abertos")
  • Ordenação clicando no header da coluna (asc/desc)
