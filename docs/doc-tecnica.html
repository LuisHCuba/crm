Decisões detalhadas

1. Frontend

— React (Vite) como SPA

Escolha

Vite + React + TypeScript. Sistema 100% painel interno (logado), sem necessidade de SEO. SPA é mais leve, build mais rápido. O build gera arquivos estáticos servidos por Nginx dentro de um container Docker.

Deploy

  • Container Docker com Nginx servindo os arquivos estáticos do build
  • Roda no mesmo servidor que a API e o banco, gerenciado pelo Portainer

2. Backend

— Node.js + Fastify em container Docker

Escolha

Node.js + Fastify + TypeScript. Separação clara do frontend. Fastify é mais rápido que Express, tem plugin de WebSocket nativo e schema validation. Roda como container Docker no Portainer.

Estrutura do projeto (sugestão)

Deploy

  • Container Docker rodando no Portainer
  • Traefik como reverse proxy (HTTPS automático, roteamento por domínio/subdomínio)
  • Ex.: api.seudominio.com → container Fastify

3. Banco de dados

— PostgreSQL em container Docker

Escolha

PostgreSQL 16+ rodando como container Docker no mesmo servidor, gerenciado via Portainer. Volume persistente para os dados.

Configuração

ItemValor
Imagem Dockerpostgres:16-alpine
Porta5432 (interna ao Docker network; não exposta publicamente)
Volume/data/postgres montado como volume persistente
RedeDocker network interna compartilhada com o container da API
Backuppg_dump agendado via cron no host (ou container de backup)

ORM — Drizzle

Drizzle ORM — leve, próximo do SQL real, tipagem forte com TypeScript. O schema é definido em código TS e gera migrations automaticamente. Melhor controle sobre queries complexas (financeiro, rateio, relatórios).

O que o ORM faz na prática: em vez de escrever SQL puro (SELECT * FROM empresas WHERE tipo = 'cliente'), você escreve em TypeScript (db.select().from(empresas).where(eq(empresas.tipo, 'cliente'))). Tem autocomplete, validação de tipos e migrations versionadas.

4. Autenticação

— Auth.js (e-mail/senha + Google)

Escolha

Auth.js (antigo NextAuth, agora funciona com qualquer framework). E-mail/senha como padrão + Google OAuth para facilitar. Sessão armazenada em JWT ou banco (configurável).

Funcionalidades

  • Login com e-mail e senha
  • Login com Google (OAuth, fácil de configurar)
  • Sessão persistente (não precisa logar toda vez)
  • Tela de login e recuperação de senha

5. Realtime

— WebSocket via Fastify

Escolha

WebSocket nativo do Fastify (plugin @fastify/websocket) ou Socket.io se precisar de fallback/rooms mais robustos. Mesma porta do servidor, sem container extra.

O que atualiza em tempo real

  • Kanban — quando alguém move um card, todos que estão vendo atualizam
  • Contas a pagar/receber — status muda, lista atualiza
  • Projetos — progresso e etapas atualizam para todos
  • Timeline/atividades — nova nota ou lembrete aparece sem refresh

6. Upload de arquivos

— Cloudflare R2

Escolha

Cloudflare R2 — compatível com API S3, sem egress fee (não paga por download), tier gratuito generoso (10 GB storage, 10M requests/mês). Ideal para anexos em registros.

Onde terá upload

  • Anexos em Negócios (propostas, contratos)
  • Anexos em Empresas/Contatos (documentos)
  • Comprovantes em Contas a pagar/receber
  • Arquivos em Projetos e tarefas

Fluxo

  • Frontend solicita URL de upload pré-assinada ao backend
  • Frontend faz upload direto para o R2 (não passa pelo servidor)
  • Backend salva a referência (URL, nome, tamanho) no banco

7. E-mail e automações

— n8n (já instalado)

Escolha

O n8n já está rodando no servidor. O sistema dispara webhooks para o n8n, que cuida do envio de e-mail e outras automações.

Exemplos de automações

GatilhoAção no n8n
Conta a receber vence amanhãE-mail de lembrete para o responsável
Conta a receber ficou atrasadaE-mail de alerta + notificação no sistema
Negócio marcado como GanhoE-mail de boas-vindas para o cliente (opcional)
Lembrete vence hojeNotificação por e-mail para o responsável
Projeto ficou atrasadoE-mail para os responsáveis do projeto

Integração

  • Backend envia webhook HTTP para o n8n quando um evento acontece
  • n8n processa e envia e-mail (via SMTP configurado lá)
  • Sem dependência de Resend/SendGrid — usa o que já tem

8. Hospedagem e deploy

— tudo no servidor próprio (Portainer + Traefik)

Arquitetura: 3 containers no mesmo servidor

ContainerO que fazEquivalente no Supabase+Netlify
web (Nginx) Serve o React buildado (arquivos estáticos) O que o Netlify fazia
api (Fastify) Recebe requisições, valida, lê/escreve no banco, retorna JSON O que o Supabase fazia (API + Edge Functions)
postgres Banco de dados O banco que o Supabase gerenciava

Traefik (reverse proxy — já rodando no servidor)

  • app.seudominio.com → container web (React)
  • api.seudominio.com → container api (Fastify)
  • n8n.seudominio.com → container n8n (já configurado)
  • HTTPS automático via Let's Encrypt

Fluxo de deploy (do código ao ar)

EtapaO que aconteceQuem faz
1. Desenvolve Escreve código no Cursor, testa local com docker compose up Você
2. Push git push para o GitHub Você
3. Deploy No Portainer, clica em "Pull and redeploy" no stack (ou webhook automático) Você (1 clique) ou automático
4. Build Portainer puxa o código novo do GitHub, rebuilda os containers (api + web) Automático
5. No ar Containers reiniciam, Traefik roteia, sistema atualizado Automático
